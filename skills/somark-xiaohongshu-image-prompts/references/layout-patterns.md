# SoMark 小红书版式模式

根据页面任务选用一个主模式。不要在同一页叠加多个模式。

## 1. 封面：价值转化

适合品牌主张、联名发布、Agent 或 RAG 主题。

- 顶部：联名标识或短标签，加 1–2 行大标题。
- 下部：`复杂文档 → SoMark → 结构化内容 / AI 应用`。
- 视觉中心：SoMark 解析入口。
- 保持三个节点，不叠加功能清单。

## 2. 痛点：原因汇聚到结果

适合解释文档为何不能被 AI 稳定使用。

- 顶部：标题加两行解释。
- 中部：两个等宽原因卡片，例如“格式多”“元素多”。
- 下部：两个原因用对称箭头汇聚到一个 AI 结果框。
- 结果控制为三项：`找不到答案｜识别失败｜总结跑偏`。
- 采用“上二下一”倒三角结构，避免左轻右重。

## 3. 原因：完整结构与混乱碎片对比

适合解释结构丢失的影响。

- 左侧：章节、段落、表格清楚的完整文档。
- 中间：醒目的 `≠` 或断裂转换线。
- 右侧：标题丢失、跨页截断、表格拆散、页眉混入。
- 标注不超过四项。

## 4. 核心流程：解析层

适合产品工作流和 RAG 入库链路。

- 链路：`文件 → SoMark → Markdown / JSON → Agent / 知识库`。
- 3:4 画布优先使用左下到右上的斜向管道，或中心 SoMark 加左右输入输出。
- SoMark 放大 20%–30%，使用最强橙色高光。
- 流程必须单向且顺序固定。

## 5. 工具分工：左右交接

适合表达 SoMark 与 Agent 的职责。

- 左侧 SoMark：`提取｜识别｜整理`。
- 右侧 Agent：`理解｜总结｜问答｜执行`。
- 中间使用单向箭头表示结构化内容交接。
- 避免画成能力竞争或双向关系。

## 6. 接入方式：双代码卡

适合 Skill / CLI 安装说明。

- 顶部突出“一行命令”。
- 中部两张等宽代码卡：Skill 接入、CLI 接入。
- 底部保留 `文档 → Markdown / JSON → Agent`。
- 没有真实命令时使用占位符，禁止虚构。

## 7. 案例：真实结果主图

适合财报、招股书、工业说明书、研报等。

- 顶部：场景标题和一句说明。
- 中部：真实结构化解析结果截图，占画面约 50%–60%。
- 底部：三项功能点，等距排列。
- 财务、工业和研究数据不得由模型重绘或改写。

## 8. 总结：四宫格检查清单

适合系列结尾和知识总结。

- 顶部：一句核心结论。
- 中部：2×2 等宽卡片，例如标题完整、跨页连贯、表格清晰、页眉干净。
- 底部：单句互动 CTA。
- 不再重复完整流程。

## 9. 互动 CTA：四选一

适合旧书数字化、场景投票或评论引导。

- 顶部：一个大问题。
- 中部：2×2 选项卡，最多四项。
- 底部：醒目的橙色 CTA 按钮。
- 选项必须可对号入座，不添加第五项。

## 10. 简化参考图

当参考图信息过载时，按以下优先级删除：

1. 重复的软件界面。
2. 底部重复卖点栏。
3. 大段代码与不可读表格。
4. 装饰性机械舱、粒子和复杂网格。
5. 非必要页码、标签和说明文字。

最终保留：标题、一个因果链、一个核心视觉和必要 CTA。
